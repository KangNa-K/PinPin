# 悬浮球吸图与拖放验证（2026-10-26）

## 已实现

- 延续 500ms 静止框选准备；继续静止 450ms 触发自动吸图，移动、松手、系统取消及第二指取消自动触发。
- 同帧本地矩形识别和裁剪；不增加窗口内容读取、不接网络识图。检测不可靠时进入现有框选调整工具。
- 独立持久化携带图片，服务重建可恢复；球显示缩略图，280ms 弧线缩入动画，遵循系统禁用动画设置。
- `ClipData` + `FileProvider` + GLOBAL/只读授权发起系统拖放；无论接收/取消均保留携带图。接收提示不冒充目标应用持久化成功。
- 保存到 `Pictures/pinpin`、分享、单次移动、主动清空。导出独立文件保证替换球内图片不立即破坏接收方正在读取的文件。

## 已执行验证

- `testDebugUnitTest`：70 项全部通过，其中 6 项新增识别测试（边界、分屏邻窗、均匀背景、无边界、非法坐标）。
- `assembleDebug`、`assembleDebugAndroidTest`、`lintDebug`：通过；lint 仍有现有依赖升级等警告，并非零警告。
- Android 15 arm64 模拟器 `emulator-5554`：全量 65 项仪器测试，64 通过、1 失败。
- 新增测试均通过：长按/移动/取消/多指，球内图片拖动，真实 WindowManager 悬浮窗发起原生拖放和读取 PNG，MediaStore 发布路径/原始分辨率/像素校验。
- 失败项：`AnnotationExitTest.attachedOverlayExitsWithInjectedStylusAfterRepeatedDrawing`，提示 `Exit action did not respond: close`；独立重跑仍失败。在 `/tmp` 导出未修改 HEAD、仅替换 applicationId 为 `com.pinpin.app.baseline` 构建安装后，同模拟器同测试也失败，确认为本次修改前可复现的问题，未扩大范围修改标注模块。

## 必须明确的未验证项

- 未连接用户三星平板，没有 One UI 8.5、小红书、三星相册或 Magpie 的端到端实测；不能视为已兼容。
- 原生拖放测试接收窗口为同 UID 的隔离测试视图，验证真实系统窗口拖放但不能替代跨应用 URI 授权实测。
- 自动识别是保守启发式，不是通用图像分割模型；合成测试通过不证明小红书真实页面的命中率。当前需要用实际页面测试误识别与漏识别。
- 未实测截图服务 → 自动裁剪 → 吸入动画整条链路；动画视觉手感也需真机验收。
- 截图缩入后必须可以松手切应用再拖出；未承诺全程不抬手跨任务切换。
- 相册未接收拖放时使用轻点球后的明确保存入口；没有伪造“拖进相册成功”。
