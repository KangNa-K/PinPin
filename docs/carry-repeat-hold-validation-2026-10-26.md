# 重复长按吸图修复（2026-10-26）

## 已复现的根因

携带图片时 BallView.onTouchEvent 提前返回 handleCarriedTouch，该分支原先只支持点击菜单和移动拖出图片，不启动静止长按计时器。因此吸入一次后，只要图片仍保留（尚未拖出、取消或目标拒收），后续长按永远不能再次触发吸图。此前测试仅验证一次拖放，未验证同一球实例多轮操作。

## 修复

- 已携带图片时，新的静止按压也启动原有 500ms 准备和 450ms 自动吸图流程；移动超过阈值仍优先拖出原图。
- 选区状态不再被携带图片的分支截断，保持事件转发到选区。
- 移动发起拖放、松手、取消与第二指及时停止长按计时器。
- 拖放结束（成功或拒收）和清空携带状态时，显式复位手势、可交互性与忙碌状态，避免下轮继承残留状态。
- 新图准备成功前旧图保持可用；截图历史和导出 URI 生命周期不变。

## 验证

- 先新增 loadedBallStationaryHoldCanArmAnotherCapture：修复前失败，提示 Loaded ball never rearms on the next stationary hold；日志 /tmp/pinpin-repeat-regression-before.log。
- 修复后 Android 15 模拟器 22 项仪器测试全部通过；包含同一窗口和控制器连续三轮长按、自动计时触发、图片准备、原生拖放、成功清空再长按，以及连续三轮拒收保留后重新吸图。
- 另回归取消、多指、松手早于载入、导出 URI 可读、相册与原选区手势。
- 70 项单元测试通过，lintDebug 和 Debug 构建通过；日志 /tmp/pinpin-repeat-final.log、/tmp/pinpin-repeat-checks.log。

## 未验证和交付边界

- 自动截图测试通过真实长按和选区计时器触发，但文件准备使用测试图片；不等同小红书页面端到端截图识别实测。
- 接收窗口为同 UID 的模拟器测试窗口，三星 One UI 8.5 和相册/Magpie 跨应用实机尚未验证。
- 本轮修复为本地源码和 Debug 产物；没有更改版本号或发布更新，公开 1.1.1 不包含此修复。
