# PinPin 性能诊断报告

日期：2026-10-11（Asia/Shanghai）

## 结论与边界

完成了本地性能诊断、扩容测试、构建检查及现有测试回归。
这不是完整的真机性能验收：耗电、温升、真实 GPU 帧率、长期泄漏、
多悬浮窗并发及端到端无障碍截图仍需真机验证。

主要优化方向：

1. 标注绘制随笔画数量线性变慢，1000 笔时软件绘制约 17.22 ms。
2. PNG 编码/原子落盘在高熵 4K 图上约 943.90 ms。
3. 5000 条数据即使编号已正确，编号检查仍约 95.27 ms。
4. 5000 Pin + 5000 历史记录的资源引用扫描约 46.18 ms。
5. 标注保存的图片合成发生在主线程，2048 方图 + 100 笔约 10.05 ms。

这些都是指定环境下的观测，不是用户设备上的 SLA 或性能等级。
没有为了得到漂亮数字而更换依赖、修改业务逻辑或忽略失败。

## 环境与方法

- 工作区：`/Volumes/KNJ/项目/项目/pinpin`，保留原有未提交改动。
- Android API 35，ARM64，1080 × 2400。
- AVD：`pinpin-review-api35`，串口 `emulator-5580`。
- 模拟器软件图形后端：SwiftShader/ANGLE。
- 图片、数据库与标注探针使用 Debug 构建，未使用 AndroidX Benchmark。
- 数据库使用随机名称的磁盘 Room 数据库；UI 测试使用独立内存数据库。
- 图片及历史数据全部为合成数据，使用随机临时目录，最终清理。
- 启动统计使用 `am start -W -S`，12 轮，丢弃前 2 轮。
- 启动为进程冷启动、文件缓存热状态、空首页、悬浮窗权限关闭。
- 普通数据库读写取 15 个样本，编号与图片取 7 个样本。
- 标注绘制取 30 个样本，每笔 21 个触摸点。
- P95 使用 nearest-rank；7/15 样本下基本等于最大值，不适合作为稳定尾延迟。
- 测量包含相应函数、协程调度以及测试断言，不等于纯 SQLite 内核耗时。
- 并未修改或安装已连接的三星 SM-X810 平板。

`EXPLAIN QUERY PLAN` 实际返回：

```text

```

编号检查在 `PinRepository.kt:287` 逐条 `findById()`，即使全部编号正确也会
产生 N 次读取。排序缺少对应索引，但当前结果中，优先级低于逐条编号查询
和资源路径规范化。增加索引需明确 Room 迁移，不应仅修改 Entity。
历史数据目前全量订阅，未来万级以上规模还需分页测试。
几何更新结果未显示随表大小明显恶化；不应因为某档更快就推断规模提升性能。
本轮未测删除后批量重新编号的写入成本，该路径可能更慢。

### 已实施优化复测

本节最终数据来自 `build/performance/final-verified/`，在同一 API 35 ARM64
模拟器、最终 APK 上重新执行 41 项仪器测试。绘制、合成采用优化后实现；数据库两种检查
使用同一轮真实临时目录（各含 5000 Pin 和 5000 历史资源文件）。

| 路径 | 优化前中位数 ms | 优化后中位数 ms | 说明 |
| --- | ---: | ---: | --- |
| 1000 笔软件画布绘制 | 17.22 | 0.51 | 预计算路径和压力画笔，增量栅格缓存；少于 64 笔不分配整屏位图 |
| 2048 方图标注退出主线程 | 10.05 | 0.95 | 快照并恢复 UI 后，在后台合成；不含 PNG 落盘 |
| 5000 条已正确编号检查 | 95.27 | 2.39 | 一次读取 id/zOrder 投影，只更新变化项 |
| 5000 + 5000 条资源检查 | 46.18¹ | 36.33 | 直接候选引用查询；保守检查目录符号链接仍为 O(文件数) |
| 4K 高熵 PNG 原子保存 | 943.90 | 941.21 | 未显示实质加速；编码仍串行限流，无损及独立文件语义不变 |

¹ 原先 46.18 ms 的测量使用纯合成路径、没有实际目录文件；不可与本轮包含
10000 个目录项的 36.21 ms 作严格等条件比较。优化前基线没有测同条件目录。
优化后本轮完整引用集合扫描为 115.62 ms，目标候选检查为 36.21 ms；
后者仍受目录扫描支配。不能声称此项随文件数或表大小为常数时间。

最终 APK 模拟器进程冷启动中位数 1102.5 ms，旧基线 920.5 ms；
软件模拟器测量波动且构建配置并非完全同轮，不能据此归因为启动回归或改善。
真实模拟器截图保存中位数 369 ms；旧轮没有同条件截图基线。
4K PNG 高熵图中位数 945.07 ms，P95 978.04 ms。性能证据是软件模拟器诊断，
不是实体设备验收或性能保证。

4K 单张 Bitmap `allocationByteCount` 为 33,177,600 字节（31.64 MiB）。
原图与输出图同时存在时为 63.28 MiB，仅是这两张图的像素存储，
不是全进程峰值，亦未包含编码缓存、图层、GPU 或硬件截图缓冲。
没有发生 OOM，但这不足以证明低内存设备安全。

Pin 图片正常加载通过 Coil 请求限制到 2048 × 2048，
所以 4K 旋转探针并不代表正常 Pin 显示时一定持有未采样 4K 原图。
4K PNG 探针对截图/图片保存路径仍有参考意义。

截图正常路径将 PNG 存入历史后再复制成 Pin 文件，这是当前可靠性/所有权设计，
不是可直接删除的冗余操作。优化必须保留历史与 Pin 独立删除的语义。

## 标注

| 场景 | 中位数 ms | 样本 P95 ms |
| --- | ---: | ---: |
| 10 笔软件绘制 | 0.41 | 0.60 |
| 100 笔软件绘制 | 1.79 | 4.38 |
| 1000 笔软件绘制 | 17.22 | 18.45 |
| 512 方图 + 100 笔退出/合成 | 3.47 | 4.41 |
| 2048 方图 + 100 笔退出/合成 | 10.05 | 14.11 |

绘制使用真实 `DrawingOverlayView.draw(Canvas(bitmap))`。
退出使用真实 `PinWindowView.exitAnnotationMode()`，反射注入测试图片；
View 未接入 WindowManager，绘图区固定 1080 × 1920，回调只回收输出 Bitmap。
因此退出测试不包含 compositor 或 PNG 保存，也不能替代真实悬浮窗完整帧时间。

60 Hz 每帧总预算约 16.67 ms。1000 笔测试仅绘图部分即接近/超过预算，
是应优先解决的扩容风险，而不是已经实测确认的真机掉帧率。
`DrawingOverlayView.kt:812` 每帧重放历史笔画，
`:932` 路径绘制时重新创建 Path/临时集合；
可优先考虑缓存笔画路径、已提交笔画图层，并验证撤销、重做和橡皮擦语义。

`PinWindowView.kt:1366` 主线程同步进入合成，
`:1428` 创建绘图 Bitmap 和源尺寸输出 Bitmap。
优化可以先快照必要状态，再移到后台合成，但必须保留退出、取消、
位图所有权与生命周期安全，本轮没有擅自实施。

## 首页滚动

- 真实 `HomeScreen`，1000 条历史记录。
- 使用同一张 256 px 绿色缩略图，属于缓存友好场景。
- 9 次索引跳转及等待空闲、12 次 swipe，全部无功能失败。
- 索引跳转耗时包含测试框架/空闲等待，不是 UI 线程耗时。
- 帧记录 37 帧，deadline missed 14（37.84%），旧口径 jank 2（5.41%）。
- 帧时间 P50 17 ms，P95 32 ms。

该样本数量小，Compose 测试时钟、Debug 和软件 GPU 会显著影响结果；
首页启动帧仅 3 帧，也不足以统计稳态帧率。
不能把 37.84% 或启动帧比例报告为实际用户掉帧率。
下一轮必须在真机 Release、真实触摸、更多帧及唯一真实图片上重新采集。

## 原始证据与复跑

最终 Debug 基线证据位于 `build/performance/verified-debug/`；最终代码复测位于
`build/performance/final-verified/`：

- `results.json`：最终 APK 的 41 条探针记录、原始样本、APK SHA-256、启动及 CPU。
- `instrumentation.txt`：最终代码的 41 个仪器测试通过。
- `frames-history-scroll.txt`：完整首页滚动帧数据。
- `memory-main.txt`、`frames-main.txt`：空首页启动后的状态。
- `cpu-idle-start.txt`、`cpu-idle-end.txt`：10 秒静置 CPU 计数。
- `crash-log.txt`：最后一轮无崩溃。

Release 启动/资源证据位于 `build/performance/verified-release/`。
构建/Lint/JVM 测试报告位于 `build/reports/profile/` 和 `app/build/reports/`。
`build/` 为生成目录，清理构建会删除证据；此报告保留关键数字。

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest assembleRelease
python3 scripts/performance_probe.py \
  --serial emulator-5580 \
  --adb "$HOME/Library/Android/sdk/platform-tools/adb"
```

脚本只接受并验证 emulator，不会自动启动模拟器或覆盖物理设备。
需先启动隔离 AVD。测试使用 Debug APK；复跑会安装两个测试 APK，
执行仪器测试，之后将模拟器内此应用的悬浮窗 app-op 恢复为 default。
不要把该脚本作为保留既有模拟器使用状态的工具。
切换签名不同的 Debug/Release APK 时，只能在隔离模拟器卸载原测试包，
不要在有用户数据的设备卸载。依赖访问仍出现 403 时，可临时使用上述
本地缓存 init script；它位于 `/tmp`，不是项目永久配置。
